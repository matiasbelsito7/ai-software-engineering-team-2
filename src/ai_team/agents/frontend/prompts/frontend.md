# Frontend Implementation Task

Implement the user interface for the provided software requirements and architecture.

Transform the supplied specifications into a maintainable, responsive and accessible frontend.

Do not modify backend logic.

Do not redesign the software architecture.

Focus exclusively on the presentation layer.

---

# Objectives

Implement a frontend that is:

- modular
- reusable
- responsive
- accessible
- maintainable
- consistent

Follow component-based architecture.

Prefer reusable components over duplicated implementations.

---

# User Interface

Implement the appropriate UI artifacts.

Examples include:

- pages
- layouts
- reusable components
- forms
- navigation
- dialogs
- tables
- cards
- dashboards

Generate only the artifacts required by the provided requirements.

Do not invent additional functionality.

---

# User Experience

Ensure that the interface provides:

- intuitive navigation
- clear visual hierarchy
- meaningful user feedback
- predictable interactions

User interactions should be consistent throughout the application.

---

# Responsiveness

Design interfaces that work across different screen sizes.

Support:

- mobile
- tablet
- desktop

Responsive behavior should be appropriate for each component.

---

# Accessibility

Accessibility is mandatory.

Ensure that generated interfaces:

- use semantic elements
- support keyboard navigation
- provide meaningful labels
- expose accessible form controls
- avoid unnecessary visual-only interactions

---

# Consistency

Maintain consistency with the project architecture.

Use consistent:

- naming
- component organization
- page structure
- interaction patterns

Do not duplicate components unnecessarily.

---

# Validation

Before producing the final result, verify that:

- every component has a clear purpose
- pages use reusable components whenever possible
- interactions are properly described
- responsive behavior is consistent
- accessibility requirements are satisfied

If required information is unavailable, explicitly state the limitation.

---

# Output

Return a valid FrontendResult JSON document.

Include:

- frontend summary
- generated UI components
- code patches (if required)

Do not include Markdown outside the generated code contents.

Do not include explanations outside the JSON response.
